## 後續維護與重新部署順序（商品已建立，不必重建）

1. 在 Studio 的 Save Experience 視窗選 Create new experience，建立「末班車｜LAST TRAIN」。保留私人狀態，不覆蓋既有遊戲。
2. 取得該遊戲的 Universe ID、起始 Place ID，填入 `products.json`。
3. 在該遊戲的 Monetization → Passes 建立前七項，設定對應圖示、介紹與售價。
4. 在 Developer Products 建立銀河商品，999 R$。外部商店顯示必須保持 **Unlisted**；只允許遊戲內先保留編號再付款。
5. 將七個 Pass ID 及一個 Developer Product ID 填入 `products.json`；不可填入別款遊戲的商品 ID。
6. 執行下面的設定工具並重新建立遊戲檔。只有資料齊全時才可使用 `--enable-billing`。
7. 將完成設定的檔案上傳同一個私人遊戲，在正式 Roblox 伺服器確認商品價格、付款取消、解鎖、重登、座位權益、限量編號及小隊傳送。
8. 檢視帳號的公開發佈資格，依實際內容完成成熟度與合規問卷、圖示、縮圖及裝置設定。公開前再確認遊戲、商品與付款結果。

```sh
python3 tools/configure_release.py LastTrain_Studio_Kit/release/products.json --check
python3 tools/configure_release.py LastTrain_Studio_Kit/release/products.json --enable-billing
rojo build LastTrain_Studio_Kit/default.project.json -o LastTrain_Studio_Kit/LastTrain.rbxlx
```

設定工具不登入 Roblox、不建立商品、不改後台售價，也不執行公開發佈。未加 `--enable-billing` 時，會儲存 ID 並保持付款關閉。

## 付款與限量設計

- 購買前檢查伺服器付款開關、目標 Universe ID、商品是否在售與玩家現有權益。
- Studio 不開啟正式付款；未設定完成時仍可預覽。
- 通行證由伺服器向 Roblox 查驗擁有權；付款視窗關閉不代表授權成功。
- 銀河商品先保留全遊戲共用編號，再開啟付款；收據由唯一的 ProcessReceipt 處理。
- 重複收據不重發編號。暫停新付款仍會繼續處理已付款收據，避免玩家付費後拿不到商品。
- 領取及保留合計最多 500；取消或中斷付款的保留編號不自動回收，原帳號可續買。畫面分別顯示已領取與保留數量。
- 銀河使用開發者商品是為了搭配付款前保留。必須保持外部 Unlisted，避免外部重複購買；遊戲內會拒絕已擁有者再次付款。
